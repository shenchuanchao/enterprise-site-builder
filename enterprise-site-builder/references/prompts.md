# 各阶段可复用提示词

> 用法：复制对应模板，替换 `{{占位}}` 后使用；括号内为执行说明，不出现在最终输出。

## P1 一句话需求解析（Step 1）

```
你是企业官网策划。把下面用户原话解析为建站简报，规则：
1. 对照 brief-schema.md 字段填空；推断值标 inferred:true，不提问。
2. 国内 B2B 默认营销获客型、响应式、中文；用户提到出口则判出海型。
3. 缺事实的产品/案例/联系方式**自动匹配行业合理默认值**（规则见 blueprints「内容自动匹配」），禁止虚构客户与数据，页面禁止出现 `{{ }}` 占位符。
4. 自动推顶部菜单 5 个（不含首页），从产品中心/解决方案/应用领域/项目案例/关于我们/新闻资讯/资质设备/资料下载/联系我们里按业务挑最相关的。
5. 只在目标冲突/行业不明/参考矛盾时提问，单次最多 3 个问题。
用户原话：{{原话}}
先输出 5-8 行「我的理解」：业务 → 判定类型与理由 → 风格配色 → 主 CTA → 待补充清单。
```

## P2 行业热门模块调研（Step 2b）

```
行业：{{行业}}；网站类型：{{类型}}。
打开 5-8 家同行业头部官网（先查案例库，不足再 web 检索），逐站记录首页模块名目，
统计高频模块，剔除与本类型无关的，按"吸引→能力→信任→转化"自动排序，输出：
1. 调研来源站点清单（URL + 各自首页模块）；
2. 选用模块清单（模块名 + 版式 + 入选理由），正文模块 ≥5 个（不含页头/页脚/悬浮菜单）；
3. 首页从上到下排版顺序；不照抄任何一家设计，不堆等分图标卡，无真实数据的数字模块不上。
```

## P3 配色（Step 2：给候选，不替客户定，未选不编码）

```
行业：{{行业}}；用户已有 VI 色：{{HEX 或 无}}；气质：{{如稳重/高级/科技感}}。
规则：
- 用户给了 VI 色：以它为主色，围绕它搭辅助/强调/背景，直接给一套即可，color_status=chosen。
- 用户没给主色调：禁止自己拍板定色，禁止跳过候选直接写页面代码；先从 taxonomy.md 行业色板派生 A/B/C 三套候选并列：
  A 稳健商务（深蓝/藏青+中性灰+金或同系强调）
  B 现代科技（深空蓝/暗色+青或靛紫强调+大留白）
  C 亲和明快（行业色降饱和+暖强调+浅底）
  每套给：主色/辅助/强调/背景 HEX、一句气质、适合的客户画像，末尾写"请选 A / B / C（或指定您的品牌色）"。
- 用户未回复选择前 color_status=pending：只能用中性临时色出结构稿并标注"配色待选"，不得锁定任何一套候选。
全部遵守 60-30-10、不用纯黑纯白、正文对比度≥4.5:1，并说明每色用在什么元素。
```

## P7 悬浮快捷菜单配置（Step 2/4/6）

```
按 quick-menu.md 拟定菜单，列入确认单让客户定：
- 是否显示（enabled 开/关）
- 位置：right-middle 右中 / right-bottom 右下 / left-middle 左中 / left-bottom 左下
- 各项显隐：电话拨打 / 微信二维码 / 获取报价锚点 / 返回顶部 / 邮件 / 其他二维码
默认：开，右中，电话+微信+报价+返回顶部；未提供真实电话/微信时自动匹配示例值（电话 0755-XXXX XXXX、微信账号文本），交付时声明可替换。
```

## P4 首页文案（Step 5，去 AI 味）

```
为 {{公司名}}（{{业务一句话}}）写营销型首页文案，风格 {{风格}}，主 CTA {{cta}}：
1. Hero 主标题（≤14 字，讲清"我们是谁+帮你解决什么+差异点"，不喊口号）、副标题（≤40 字）。
2. 3-4 条核心优势，每条：小标题 + 一句证据化描述（具体做什么板/多少层/几天交/控什么参数；无真实数据用行业常规范围或"按工艺窗口执行"，不用形容词补位）。
3. 主/次 CTA 按钮文案各 1 组。
4. 禁用空词：赋能、助力、一站式、全方位、生态、闭环、顶尖、一流、卓越、匠心、领航、打造、智慧未来；不写排比三连空话；句子短、口语、像业务员当面介绍。
```

## P8 编码前门禁自检（Step 5→Step 6 之间，逐条过，不过不写码）

```
输出代码前先自查，任一为否就停下，只发待确认项，不输出页面：
[ ] color_status=chosen（已给 VI 或已选 A/B/C）；若 pending，是否已完整展示 A/B/C 候选？未展示禁止写码。
[ ] pending 状态下是否只用中性临时色并标注"配色待选"，未把候选写死成品牌色？
[ ] 悬浮菜单开关/位置/各项显隐已拟定并列出？
[ ] 页面零 `{{ }}` 占位符；未知信息已自动匹配行业合理默认值，无虚构客户/数据/案例？
[ ] 栏目蓝图与文案已定稿？
任一条不满足：输出待确认清单 + 配色候选，等待用户，不要先给代码。
```

## P9 内页生成（Step 6b，首页确认后）

```
首页已获用户确认。按确认的 5 个菜单逐个做内页，复用首页配色/导航/页脚/悬浮菜单：
- 列表页（产品/案例/新闻）：页头（banner 背景图）标题+一句话 → 分类筛选条 → 卡片/表格列表 → 分页控件（数据不足时仅样式）→ 询盘 CTA。
- 详情页（产品/案例/文章）：面包屑 → 标题 → 参数表/正文 → 相关推荐 → 底部询盘条。
- 关于页：简介/历程时间线/资质墙/工厂图位；联系页：表单+电话/微信/邮箱/地址+地图区（上线后替换）。
- 无真实案例/新闻建行业匿名条目骨架，不虚构客户名与数字；页间链接互通、无死链，当前导航项高亮；未知信息自动匹配合理默认值，页面零 {{ }}。
```

## P6 验收自查（Step 7）

```
对照 qa-checklist.md 逐项检查本次产出，输出三栏：通过 / 待补（写明缺什么）/ 阻塞。
重点：首页正文模块≥5（不含页头/页脚/悬浮菜单）、手机端单列可点、正文对比度、CTA 可达、悬浮菜单位置/显隐与确认一致且不遮主按钮、
微信弹层可用、返回顶部滚动后出现、无虚构案例与客户 logo、无死链、
每页有独立 title 与 meta description（自动匹配默认值）；联系方式为默认值而非假号、交付时声明清单；配色若客户未定，页面为中性临时色并标注"配色待选"而非擅自锁定。
去 AI 味：无紫蓝霓虹渐变/玻璃拟态滥用/等分图标卡套娃/emoji 功能图标；无"赋能/一站式/顶尖/匠心"空词；
遮掉公司名换行业不能直接套用。
```
